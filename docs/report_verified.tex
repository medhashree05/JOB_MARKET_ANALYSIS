% ---------- Abstract ----------
\section*{Abstract}
Modern online recruitment portals publish tens of thousands of unstructured, heterogeneous job postings weekly. Extracting actionable labour-market intelligence from this corpus requires scalable, fault-tolerant batch architectures capable of handling noisy free text, multi-valued skill lists, inconsistent geographic spellings, and non-standard salary disclosures. In this project, an end-to-end Big Data processing pipeline is designed, implemented, and empirically verified over a primary dataset of 97,929 Indian job postings. 

The pipeline integrates three core Hadoop ecosystem layers: (1)~\textbf{HDFS Ingestion and Sanitization}, which executes deterministic schema validation and deduplication, retaining 97,679 verified postings; (2)~\textbf{Apache Pig (Pig Latin on MapReduce)}, which executes parallel tokenization, normalisation, distinct job--skill projection, and multi-dimensional aggregation; and (3)~\textbf{Apache Hive}, which exposes the aggregated partitions as structured external tables via \code{OpenCSVSerde} and evaluates analytical HiveQL queries across job roles, skills, hiring hubs, and salary benchmarks. A decoupled \textbf{Streamlit presentation layer} provides an interactive dashboard with seven pages and dynamic CSV export functionality. 

A rigorous technical audit of the repository resolved prior numerical reporting discrepancies: the variance between 97,679 and 97,715 postings and between 18,320 and 18,310 Bengaluru postings is formally traced to a 36-row newline export fragmentation artifact in unquoted intermediate CSV dumps. Furthermore, because the primary dataset represents an active cross-sectional scrape containing relative recency strings rather than multi-year calendar dates, temporal trend measurement is structurally constrained. To address this limitation, the \textbf{Skill Demand Velocity Index (SDVI)} is critically evaluated as a conceptual extension; a mathematical audit demonstrates the limitations of single-scalar quadrant thresholding and establishes an orthogonal two-dimensional classification framework.

\section{Introduction}
Labour market intelligence provides critical signals for curriculum planning, workforce development, and industrial hiring strategy. However, large-scale recruitment data is notoriously noisy: identical job titles appear with arbitrary capitalization and parenthetical annotations; skill requirements are packed into single comma-delimited strings; salary disclosures are sparse, right-skewed, and multi-currency; and posting dates frequently rely on relative timestamps (e.g., ``3 Days Ago'') without absolute scrape references. Processing such corpora at scale exceeds the capabilities of in-memory single-node spreadsheets and demands a distributed, fault-tolerant Big Data architecture.

This project delivers a complete, reproducible batch processing pipeline tailored for large-scale job market intelligence:
\begin{itemize}
  \item \textbf{Storage Layer (HDFS):} Distributed ingestion, block-level storage, replication, and data validation.
  \item \textbf{Transformation Layer (Apache Pig):} Procedural MapReduce data flows for schema enforcement, string parsing, skill array flattening, and grouped aggregations.
  \item \textbf{Analytical Warehouse (Apache Hive):} Schema-on-read external table structures, \code{OpenCSVSerde} parsing for text preservation, and HiveQL analytical querying.
  \item \textbf{Exploration Layer (Streamlit \& Plotly):} A decoupled, responsive presentation dashboard delivering executive KPIs, geographic drill-downs, and filtered data exploration.
\end{itemize}

\subsection{Project Scope and Empirical Boundaries}
A fundamental principle of scientific computing is maintaining absolute fidelity to empirical evidence. % ---------- 2. Literature Survey ----------
\section{Literature Survey}
\subsection{Distributed Batch Computing Foundations}
The architectural foundation of large-scale distributed computing was formulated by Dean and Ghemawat~\cite{dean2004mapreduce}, who introduced the MapReduce programming paradigm to parallelise computation across commodity clusters with automatic data partitioning, scheduling, and fault recovery. The underlying storage fabric, the Hadoop Distributed File System (HDFS), described by Shvachko et al.~\cite{shvachko2010hdfs}, provides high-throughput streaming access to large files via block-level distribution across DataNodes coordinated by a centralised NameNode metadata service.

\subsection{High-Level Dataflow and Warehousing Abstractions}
Writing native MapReduce in Java involves substantial boilerplate and complex join/aggregation management. To abstract this complexity, Olston et al.~\cite{olston2008pig} developed Pig Latin, a procedural dataflow language that compiles high-level transformations (\code{FILTER}, \code{FOREACH}, \code{GROUP}, \code{COGROUP}, \code{FLATTEN}) into directed acyclic graphs of MapReduce jobs. Concurrently, Thusoo et al.~\cite{thusoo2009hive} introduced Apache Hive, establishing the schema-on-read data warehousing model. Hive projects SQL-like structures (HiveQL) over distributed files, supporting metadata separation, partition pruning, and complex serde implementations such as \code{OpenCSVSerde}. White~\cite{white2015hadoop} provides comprehensive architectural guidance on integrating HDFS, Pig, and Hive within production enterprise clusters.

\subsection{Skill Extraction and Labour Market Analytics}
Analysing online recruitment advertisements has emerged as a vital discipline in computational economics. Khaouja et al.~\cite{khaouja2021survey} surveyed text mining and natural language processing approaches for skill extraction, noting that while machine-learning taggers offer high specificity, distributed rule-based tokenisation remains the gold standard for high-throughput batch pipelines. Djumalieva and Sleeman~\cite{djumalieva2018taxonomy} demonstrated that data-driven skill taxonomies derived from online vacancy text accurately track emergent industry requirements long before formal occupation classification systems (such as O*NET or SOC) are updated.

\subsection{Momentum Metrics and Percentage Distortion}
In longitudinal skill analysis, ranking by raw frequency introduces \textit{incumbent inertia}: foundational skills such as SQL and Python consistently dominate total counts regardless of current market acceleration. Conversely, naive percentage growth suffers from severe \textit{sparsity distortion}: a tool expanding from 1 to 3 postings exhibits $+200\%$ growth, vastly overshadowing an enterprise tool expanding from 500 to 750 postings ($+50\%$). Weighting growth by logarithmic volume, as conceptualised in velocity metrics, addresses both pitfalls.

\subsection{Task 1: Ingestion, Sanitization, and Schema Contract}
The raw dataset (\code{indian-job-market-dataset-2025.xlsx}) contains 97,929 recruitment postings. Ingestion and data hygiene are implemented in Python (\code{01_convert_xlsx_to_csv.py} and \code{02_clean_data.py}):
\begin{enumerate}
  \item \textbf{Deduplication:} 247 exact duplicate rows were detected and purged. A subset deduplication on \code{job_id} identified and removed 3 additional records, eliminating exactly \textbf{250 duplicate rows}.
  \item \textbf{Schema Validation:} Mandatory constraints were asserted on primary identifiers: $\text{job\_id} \neq \emptyset$, $\text{job\_title} \neq \emptyset$, and $\text{location\_raw} \neq \emptyset$. All 97,679 unique records satisfied required field completeness.
  \item \textbf{Salary Normalisation:} In the raw scrape, 64,076 postings lacked compensation figures, labelled as \code{"Not disclosed"} with min/max salary artificially hardcoded to \code{0.0}. To prevent severe downward bias, these values were converted to \code{NaN} (missing). Postings explicitly labelled \code{"Unpaid"} (333 records) retained \code{0.0} as a valid compensation metric.
  \item \textbf{Primary Location Extraction:} Multi-location strings (e.g., \code{"Kolkata(Chinar Park)"} or \code{"Noida, Greater Noida"}) were parsed to isolate the primary municipal hiring center (\code{"Kolkata"}, \code{"Noida"}) while retaining \code{location_raw} for auditing.
  \item \textbf{Sanitised Retention:} The validated dataset retains exactly \textbf{97,679 records} (99.74\% retention) and is staged to HDFS at \code{/jobmarket/cleaned/jobs_cleaned.csv}.
\end{enumerate}

\subsection{Task 2: Large-Scale Transformation Using Apache Pig}
The transformation script (\code{task2_jobmarket.pig}) loads the cleaned CSV from HDFS using Piggybank's \code{CSVExcelStorage(',')}, drops the header row, and executes five core MapReduce transformation jobs:
\begin{itemize}
  \item \textbf{String Case and Whitespace Normalisation:} Applies \code{LOWER(TRIM())} across titles and locations.
  \item \textbf{Skill Array Explosion:} Evaluates \code{FLATTEN(TOKENIZE(skills, ','))}, strips whitespace, purges null and \code{"not specified"} tokens, and enforces \code{DISTINCT} across \code{(job_id, skill)} pairs so no posting votes multiple times for the same tool.
  \item \textbf{Multi-Dimensional Grouping:} Aggregates posting volume by skill, by primary location, and by job role.
  \item \textbf{Strict Currency Separation:} Computes minimum, maximum, and mean salary by role and by location, filtering $\text{avg\_salary} > 0$ and partitioning INR and USD into non-overlapping groups.
  \item \textbf{Recency Binning:} Groups relative posting strings into four recency categories (\code{0-1 Days}, \code{1-7 Days}, \code{7-30 Days}, \code{30+ Days}, \code{Unknown}).
\end{itemize}

\subsection{Task 3: Analytical Data Warehousing in Apache Hive}
Apache Hive maps relational schemas over the Pig output directories using \code{OpenCSVSerde}. The use of \code{OpenCSVSerde} is architecturally crucial: because job titles and company names frequently contain embedded commas, standard line-delimited text parsers fail, whereas \code{OpenCSVSerde} correctly preserves text tokens enclosed in quotation marks.

Listing~\ref{lst:hiveddl} shows the external table specification for the core skills warehouse table:
\begin{lstlisting}[language=SQL, caption={Hive DDL mapping external table over Pig tokenised output.}, label={lst:hiveddl}]
CREATE EXTERNAL TABLE IF NOT EXISTS job_skills (
    job_id STRING,
    job_title STRING,
    location STRING,
    currency STRING,
    skill STRING
)
ROW FORMAT SERDE 'org.apache.hadoop.hive.serde2.OpenCSVSerde'
STORED AS TEXTFILE
LOCATION '/jobmarket/processed/skills';
\end{lstlisting}

Analytical HiveQL queries in \code{03_analysis.sql} evaluate ranking and salary distributions. To prevent single-posting anomalies from corrupting compensation benchmarks, salary queries enforce \code{HAVING COUNT(*) >= 5}.

\textbf{Root Cause of the 36-Row Variance:}
Inspecting the 36 anomalous rows in \code{dashboard/data/jobs_cleaned.csv} revealed that raw vacancy descriptions contained literal carriage-return characters (\code{\textbackslash r\textbackslash n}) inside company names and job titles. When Pig/Hive exported these records without full RFC-4180 multiline encapsulation, single records fractured into multiple lines. For example, line 26,946 of the export file contains:
\begin{quote}
\code{job\_id: "Bengaluru", job\_title: ",cargill,1360428,bengaluru...", location: "api integration"}
\end{quote}
Here, the location token was shifted into the primary key column. Consequently, the true dataset size is rigorously established as \textbf{97,679}.

\textbf{Critical Analytical Observations on Salary:}
\begin{enumerate}
  \item \textit{Outlier Sensitivity:} The \textit{deputy manager} category ranks highest in arithmetic mean (\rupee 9.75M), but forensic inspection reveals this is entirely distorted by a single extreme posting of \rupee 82,500,000 (8.25 Crore INR) against a baseline minimum of \rupee 85,000. \end{itemize}

In accordance with strict academic integrity standards, Phase~II is classified as **unimplemented and unverified** as an empirical pipeline. However, the proposed velocity methodology represents a valuable conceptual model worthy of rigorous theoretical evaluation.

\subsection{Mathematical Formulation and Evaluation of SDVI}
The proposed Skill Demand Velocity Index is defined as:
\begin{equation}
\text{growth\_rate} = \frac{\text{Mentions}_t - \text{Mentions}_{t-1}}{\text{Mentions}_{t-1}}
\label{eq:growth}
\end{equation}
\begin{equation}
\text{SDVI} = \text{growth\_rate} \times \ln(1 + \text{Mentions}_t)
\label{eq:sdvi}
\end{equation}

\textbf{Validation of Stated Examples:}
\begin{itemize}
  \item \textit{Low-Volume Jump ($2 \rightarrow 4$ mentions):} $\text{growth\_rate} = (4-2)/2 = 1.0$ ($+100\%$). $\text{SDVI} = 1.0 \times \ln(5) \approx \mathbf{1.61}$.
  \item \textit{High-Volume Jump ($100 \rightarrow 150$ mentions):} $\text{growth\_rate} = (150-100)/100 = 0.5$ ($+50\%$). $\text{SDVI} = 0.5 \times \ln(151) \approx \mathbf{2.51}$.
\end{itemize}
The logarithmic damping function successfully curbs percentage inflation for low-frequency niche skills while preserving momentum signals for high-volume tools.

\subsection{Mathematical Critique of Quadrant Boundary Rules}
The original report proposed classifying skills into four quadrants based on $\text{growth\_rate}$ and $\text{median(SDVI)}$:
\begin{center}
\small
\begin{tabular}{@{}ll@{}}
\toprule
\textbf{Quadrant Label} & \textbf{Proposed Decision Rule} \\
\midrule
Emerging & $\text{growth\_rate} > 0$ and $\text{SDVI} > \text{median(SDVI)}$ \\
Established Growth & $\text{growth\_rate} > 0$ and $\text{SDVI} \le \text{median(SDVI)}$ \\
Stable Core & $\text{growth\_rate} \le 0$ and $\text{SDVI} > \text{median(SDVI)}$ \\
Declining & $\text{growth\_rate} \le 0$ and $\text{SDVI} \le \text{median(SDVI)}$ \\
\bottomrule
\end{tabular}
\end{center}

\textbf{Mathematical Flaw in the Stable Core Rule:}
\begin{enumerate}
  \item Because volume is non-negative ($\text{Mentions}_t \ge 0$), the scaling term $\ln(1 + \text{Mentions}_t)$ is strictly non-negative ($\ge 0$).
  \item Therefore, the sign of $\text{SDVI}$ is identical to the sign of $\text{growth\_rate}$:
  $$\text{growth\_rate} \le 0 \implies \text{SDVI} \le 0$$
  \item In an active, growing labour market, the median SDVI across active skills is strictly positive ($\text{median(SDVI)} > 0$).
  \item Consequently, for any skill with non-positive growth ($\text{growth\_rate} \le 0$):
  $$\text{SDVI} \le 0 < \text{median(SDVI)}$$
  \item Thus, the rule $\text{growth\_rate} \le 0 \land \text{SDVI} > \text{median}$ is \textbf{mathematically impossible to satisfy}.
  \item A ubiquitous core incumbent (e.g. Python or SQL with 10,000 mentions and $0\%$ growth) receives $\text{SDVI} = 0$. Since $0 \le \text{median}$, the rule misclassifies the vital foundation of the industry as \textbf{``Declining''}!
\end{enumerate}

\subsection{Recommended Methodological Correction: Orthogonal 2D Classification}
To resolve this defect, volume and velocity must be evaluated along independent, orthogonal coordinate axes rather than conflating volume into the growth multiplier:
\begin{itemize}
  \item \textbf{Y-Axis (Momentum):} Normalised Growth Rate $\Delta_t = (\text{Mentions}_t - \text{Mentions}_{t-1}) / (\text{Mentions}_{t-1} + \epsilon)$, where $\epsilon = 1$ prevents division-by-zero on newly emergent skills.
  \item \textbf{X-Axis (Presence):} Logarithmic Volume $V_t = \ln(1 + \text{Mentions}_t)$.
\end{itemize}

The corrected, mathematically sound classification taxonomy is defined as:
\begin{center}
\small
\begin{tabular}{@{}lll@{}}
\toprule
\textbf{Classification Category} & \textbf{Mathematical Boundary Rule} & \textbf{Market Interpretation} \\
\midrule
\textbf{Emerging} & $\Delta_t > +\delta$ and $V_t \le \text{Median}(V)$ & High growth, early adoption phase \\
\textbf{Established Growth} & $\Delta_t > +\delta$ and $V_t > \text{Median}(V)$ & High growth, high enterprise adoption \\
\textbf{Stable Core} & $|\Delta_t| \le \delta$ and $V_t > \text{Median}(V)$ & Flat growth, dominant market incumbent \\
\textbf{Declining / Niche} & $\Delta_t < -\delta$ (or $|\Delta_t| \le \delta \land V_t \le \text{Med}$) & Cooling demand or obsolete technology \\
\bottomrule
\end{tabular}
\end{center}
where $\delta = 0.05$ represents a $5\%$ stability band around zero growth.

% ---------- 8. Data Integrity & Limitations ----------
\section{Data Integrity, Quality \& Limitations}
\begin{itemize}
  \item \textbf{Currency Isolation:} The pipeline strictly segregates INR and USD transactions. Undisclosed compensation is handled by null propagation rather than zero-imputation, avoiding artificial deflation of salary means.
  \item \textbf{Text Normalisation Boundaries:} Normalisation in Task 2 enforces lowercasing and whitespace trimming. It does not resolve semantic synonyms (e.g., merging \code{"sde"} with \code{"software development engineer"}). Implementing a canonical ontology mapping layer is recommended for production deployment.
  \item \textbf{Absence of Longitudinal Dates:} The primary dataset represents a single scrape snapshot containing relative recency strings. It cannot support multi-year growth curves without fabricating dates.
  \item \textbf{Decoupled Dashboard Presentation:} The Streamlit application operates independently of active cluster services. While convenient for stakeholder review, production deployments require automated scheduling (e.g. Apache Oozie or Airflow) to refresh exported datasets.
\end{itemize}

% ---------- 9. Conclusion & Future Work ----------
\section{Conclusion \& Future Work}

\subsection{Conclusion}
This project successfully designed, implemented, and audited a scalable, batch processing Big Data pipeline over 97,929 Indian job postings. By orchestrating HDFS for fault-tolerant distributed storage, Apache Pig for MapReduce-based transformation and tokenisation, and Apache Hive for structured SQL analytics via \code{OpenCSVSerde}, the system achieves end-to-end data processing without single-node memory bottlenecks. 

The empirical findings establish that enterprise software roles (\textit{application developer}) and foundational technical skills (\textit{Python}, \textit{SAP}, \textit{Java}, \textit{SQL}) dominate national recruitment volume, with over 38.5\% of hiring opportunities concentrated in Bengaluru, Hyderabad, and Pune. Disclosed compensation exhibits pronounced right-skewness, with specialized data engineering and architecture roles leading technology sector pay. Prior reporting discrepancies were conclusively resolved as intermediate CSV export formatting artifacts. Finally, the limitations of snapshot data were addressed through a rigorous mathematical evaluation of the Skill Demand Velocity Index.

\subsection{Future Work}
\begin{enumerate}
  \item \textbf{Longitudinal Multi-Scrape Ingestion:} Deploy scheduled weekly web scrapers writing into dated HDFS directories (e.g., \code{/jobmarket/raw/year=YYYY/month=MM/}) to enable true calendar time-series analytics in Hive.
  \item \textbf{Ontological Synonym Mapping:} Integrate a domain-specific labour market ontology to canonicalize disparate spelling variations and synonymous role titles into standard occupation codes.
  \item \textbf{Implementation of Orthogonal SDVI:} Implement the corrected 2D velocity taxonomy in HiveQL using partitioned \code{LAG()} window queries over multi-month datasets.
  \item \textbf{Automated Pipeline Orchestration:} Transition from manual bash runners to an automated workflow orchestrator such as Apache Airflow to coordinate cluster startup, ingestion, Pig execution, and dashboard export refreshes.
\end{enumerate}
