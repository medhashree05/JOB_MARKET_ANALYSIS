# Task 3 - Hive Job Market Intelligence

## Objective

Use the HDFS datasets generated by Task 2 to create Hive tables and answer the job market questions:

- Most demanded roles, skills, and locations
- Average, minimum, and maximum salary by role
- Average salary by location and currency
- Skill and job-role relationships
- Posting recency distribution
- Skill demand over explicit time periods and emerging-skill growth

## Prerequisites

Hadoop, HDFS, and Hive must be running. Task 2 must have completed successfully and created:

```text
/jobmarket/processed/jobs
/jobmarket/processed/skills
/jobmarket/processed/skills_demand
/jobmarket/processed/location
/jobmarket/processed/salary
/jobmarket/processed/salary_location
/jobmarket/processed/time_based
```

If Hadoop is not running in WSL, start it before Task 3:

```bash
export HADOOP_HOME=/usr/local/hadoop
export HIVE_HOME=/usr/local/hive
export PIG_HOME=/usr/local/pig
export JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64
export PATH=$JAVA_HOME/bin:$HADOOP_HOME/bin:$HADOOP_HOME/sbin:$HIVE_HOME/bin:$PIG_HOME/bin:$PATH
start-dfs.sh
start-yarn.sh
mapred --daemon start historyserver
hdfs dfsadmin -safemode leave
hdfs dfs -ls /jobmarket/processed
```

Confirm the services with `jps`. Normally you should see `NameNode`, `DataNode`, `ResourceManager`, `NodeManager`, and `JobHistoryServer`. The JobHistoryServer web page is normally available at `http://localhost:19888` and its RPC endpoint is `localhost:10020`.

The processed Pig files are headerless quoted CSV. Hive uses `OpenCSVSerde` and external HDFS locations so commas inside job titles, company names, locations, and skills are preserved.

## Run

From the repository root in WSL:

```bash

```

Or run the stages individually:


The analysis script prints each result set to the Hive client. To save a result, redirect the command output or run an individual query with `hive -e`.

## Results for the report

Use these interpretations when writing the final report:

| Result | Meaning |
|---|---|
| Top job roles | Number of postings for each normalized role |
| Top skills | Number of job postings requiring each skill |
| Location demand | Number of postings in each cleaned primary location |
| Salary by role/location | Salary values remain separated by currency |
| Skill-role combinations | Roles most associated with individual skills |
| Posting recency | Current dataset recency buckets, not historical hiring years |
| Emerging skills | Positive growth only where explicit years are present |
| Data quality | Invalid salaries, missing required fields, and duplicate IDs |

Do not describe `posted_raw` as a complete 2024/2025/2026 historical trend. The source mostly contains relative text such as `6 Days Ago` and `Just Now`; the Hive trend table assigns those rows to `unknown`.

## Further analysis

The bottom five queries in `scripts/04_screenshot_queries.sql` are reusable extensions for company demand, experience demand, currency-level salary, cross-role skills, and role-location demand. To add a new analysis:

1. Add a labeled query to `scripts/03_analysis.sql` for the normal report, or to `scripts/04_screenshot_queries.sql` for screenshot output.
2. Start with `USE jobmarket;`.
3. Use the table names and columns in the schema table below.
4. Keep currencies separate when calculating salary.
5. Add `LIMIT` while exploring large grouped results.
6. Run it with `hive -S -e` or rerun the SQL file.

Useful examples:

```bash
# Top companies
hive -S -e "USE jobmarket;
SELECT company_name, COUNT(*) AS job_count
FROM jobs
GROUP BY company_name
ORDER BY job_count DESC
LIMIT 20;"

# Skills used across the largest number of roles
hive -S -e "USE jobmarket;
SELECT skill, COUNT(DISTINCT job_title) AS distinct_roles
FROM job_skills
GROUP BY skill
ORDER BY distinct_roles DESC
LIMIT 20;"

# Salary by currency without mixing INR and USD
hive -S -e "USE jobmarket;
SELECT currency, ROUND(AVG(avg_salary), 2) AS average_salary,
	   COUNT(*) AS job_count
FROM jobs
WHERE avg_salary IS NOT NULL
GROUP BY currency;"
```

For repeated executions, Task 2 must be rerun first when its HDFS outputs change. The Task 3 runner checks all seven processed HDFS directories before creating Hive metadata.

To verify loaded row counts separately:

```bash
hive -e "USE jobmarket; SELECT 'jobs' AS table_name, COUNT(*) AS row_count FROM jobs UNION ALL SELECT 'job_skills', COUNT(*) FROM job_skills UNION ALL SELECT 'job_locations', COUNT(*) FROM job_locations UNION ALL SELECT 'job_salary', COUNT(*) FROM job_salary;"
```

## Time-trend limitation

The source dataset's `posted_raw` field primarily contains relative values such as `6 Days Ago` and `Just Now`, not reliable calendar dates. `02_build_skill_trends.sql` extracts an explicit year only when one is present, for example `2025` or `'25`; all other rows are assigned to `unknown`.

The emerging-skill query excludes `unknown`, so it does not present recency buckets as fake calendar trends. For a complete 2024/2025/2026 comparison, Task 1 must provide a real posting date or a dated snapshot of the dataset.

## Outputs covered

`03_analysis.sql` produces the final analytical result sets for top roles, top skills, location demand, salary by role, salary by location, skill-role combinations, recency, explicit-period trends, emerging skills, and data-quality checks.

## Troubleshooting

- `Input path does not exist: /jobmarket/cleaned/jobs_cleaned.csv`: complete Task 1 and run `03_hdfs_load.sh`.
- `Piggybank jar does not exist`: set the `REGISTER` path in the Pig script to your local Pig installation; this repository uses `/usr/local/pig/lib/piggybank.jar`.
- Pig retries `0.0.0.0:10020`: the Hadoop client has no explicit JobHistoryServer address. Use `bash task2_pig/scripts/run_task2_pig.sh`; it sets `mapreduce.jobhistory.address=localhost:10020`, starts the history server, and verifies all Pig `_SUCCESS` markers.
- Task 3 reports missing `skills_demand`: Task 2 did not finish all outputs. Run `bash task2_pig/scripts/run_task2_pig.sh` and wait for every output directory to contain `_SUCCESS`.
- `Name node is in safe mode`: run `hdfs dfsadmin -safemode leave` after HDFS has started.
- `SLF4J` or `NativeCodeLoader` warnings: these are common environment warnings and are not, by themselves, failures.
